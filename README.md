# Мои Рейсы — версия 2.0.0

Добавлен модуль учёта топлива: ручная регистрация заправок, объём, цена за литр, сумма, пробег одометра, АЗС, тип топлива, привязка к рейсу и URI чека. История и сводные расходы отображаются в отдельном разделе «Топливо». Средний расход оценивается по суммарному объёму топлива и диапазону одометра между крайними записями; для точного расчёта рекомендуется фиксировать заправки при одинаковом сценарии (например, полный бак).

Записи топлива включены в ZIP-резервную копию и восстановление. Для существующей базы добавлена миграция Room 4→5.

**Проверка:** исходный проект обновлён, но Gradle-сборка и тестирование на физическом устройстве в этой среде не выполнялись.

# Мои Рейсы — Android

Нативный Android-проект для личного учёта грузовых рейсов.

## Что включено в стартовую версию
- Локальная база Room: рейсы, дневные записи, документы и GPS-точки.
- Создание рейса с точками отправления/прибытия, грузом, накладной, отправителем и получателем.
- Ручной ввод километража и времени по каждому дню с автоматическим суммированием.
- Выбор фотографий/файлов документов из системного файлового выбора.
- Сервис фоновой GPS-записи точек маршрута с постоянным уведомлением.
- Просмотр списка рейсов и карточки рейса.

## Сборка
1. Установите Android Studio (актуальную стабильную версию) и Android SDK 35.
2. Откройте папку проекта `MoiReisy` в Android Studio.
3. Дождитесь Gradle Sync.
4. Подключите Android-телефон с USB debugging или создайте эмулятор.
5. Нажмите Run.

Для APK: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
Обычно файл появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Разрешения
При запуске GPS-трекинга Android запросит разрешение на геолокацию. На Android 13+ также может потребоваться разрешение на уведомления. Для продолжительной фоновой записи Android может попросить отдельно разрешить доступ к геолокации «Всегда» в настройках приложения.

## Важные замечания первой версии
- GPS-трек пишется в локальную таблицу точек; карта и построение линии на карте пока не подключены.
- GPS-километраж пока отображается в уведомлении сервиса, а дневной/общий пробег в карточке рейса ведётся через ручные дневные записи. Следующий этап — объединить GPS-расстояние с дневным журналом и добавить карту.
- Файлы документов сохраняются как URI системного хранилища. Не удаляйте исходные файлы из телефона; в следующем этапе можно добавить копирование в приватную папку приложения и резервное копирование.
- Это исходный проект для дальнейшей сборки и тестирования, а не уже подписанный релизный APK.


## Облачная сборка APK через GitHub Actions

В проект добавлен workflow `.github/workflows/android-apk.yml`.

1. Создайте пустой репозиторий на GitHub.
2. Загрузите в него всё содержимое этой папки (включая скрытую папку `.github`).
3. Откройте вкладку **Actions** в репозитории.
4. Выберите **Build Android APK** и нажмите **Run workflow**. Также сборка запускается автоматически при push в `main` или `master`.
5. После завершения откройте запуск workflow и скачайте artifact **MoiReisy-debug-apk**. Внутри будет `app-debug.apk`.

Это debug APK для личной установки и тестирования. Для публикации в Google Play потребуется отдельная release-сборка с ключом подписи.


## Обновление 1.4.0 — финансовый отчёт

Добавлено:
- финансовый отчёт за сегодня, текущую неделю, текущий месяц и всё время;
- сумма расчётного заработка, общий/гружёный/порожний километраж и средняя ставка;
- история начислений по дневным записям;
- выбор типа пробега при ручном добавлении дневной записи;
- ставка по умолчанию в настройках (7 ₽/км) и индивидуальная ставка в форме нового рейса;
- ставка и тип пробега сохраняются в записи, поэтому изменение ставки по умолчанию не пересчитывает прошлые начисления;
- миграция Room с версии базы 1 на 2, существующие записи получают ставку 7 ₽/км и тип «с грузом».

Важно: финансовый отчёт сейчас рассчитывается по сохранённым дневным записям пробега. GPS-точки сами по себе пока не разделяются на гружёные/порожние участки и не включаются в заработок автоматически. Чтобы километраж попал в финансовый отчёт, внесите его через «Добавить дневной пробег» и выберите тип участка. APK не собирался и приложение не проверялось на реальном устройстве в этой среде.


## Обновление 1.5.0 — GPS и финансовый отчёт связаны

- При старте GPS водитель выбирает тип текущего рабочего участка: «с грузом» или «без груза».
- Тип можно переключить прямо во время записи; участок, пересекающий момент переключения, не начисляется ни в одну категорию, чтобы не смешивать типы.
- Каждая принятая GPS-дистанция от 0,01 до 5 км автоматически создаёт финансовую запись с датой, типом пробега и зафиксированной ставкой рейса.
- Фильтруются неточные GPS-фиксы с точностью хуже 50 м и повторные фиксы с интервалом менее 5 секунд.
- GPS-километры сразу входят в общий пробег рейса и в финансовый отчёт; ручные записи остаются доступны. Не добавляйте вручную те же километры, которые уже были записаны GPS, иначе получится двойной учёт.
- В истории отчёта и карточке рейса GPS-начисления группируются по дате, типу и ставке, чтобы не выводить отдельную строку на каждую GPS-точку.
- В карточке рейса отображается сумма начислений.
- Схема базы обновлена до версии 3: для GPS-точек сохраняются тип пробега и ставка; добавлена миграция 2→3.

Ограничения и проверка: начисление производится по прямолинейному расстоянию между соседними принятыми GPS-фиксациями, поэтому это оценка фактически записанного GPS-трека, а не показания одометра. Пропуски GPS и фильтрация выбросов могут немного уменьшать расстояние. Если сервис остановить, пауза не оплачивается; после повторного запуска новый GPS-отрезок начинается с первой новой точки. Проект не был собран Gradle и не протестирован на физическом телефоне в этой среде.

## Обновление 1.6.0 — паузы, остановки и учёт времени

Добавлено:
- кнопка «Пауза» во время активной GPS-записи;
- причины остановки: погрузка, разгрузка, ожидание, отдых и другая остановка;
- при паузе GPS-обновления прекращаются, поэтому расстояние и заработок не начисляются;
- кнопка «Продолжить» закрывает текущую паузу и возобновляет GPS-запись с чистой стартовой GPS-точкой — интервал через паузу не попадает в пробег;
- кнопка «Стоп» завершает GPS-запись и закрывает незавершённую паузу;
- в карточке рейса отображаются причины, даты и длительность остановок, а также суммарное время пауз;
- добавлена оценка времени движения по последовательным GPS-фиксациям; интервалы с паузами, большими разрывами GPS или скоростью ниже 2 км/ч не включаются;
- состояние активного рейса и паузы сохраняется в настройках приложения, чтобы экран мог восстановить статус после перезапуска интерфейса;
- база Room обновлена до версии 4, добавлена таблица `trip_pauses` и миграция 3→4 без удаления существующих рейсов, GPS-точек и начислений.

Ограничения: оценка времени движения зависит от частоты и качества GPS и не является официальным учётом рабочего времени водителя. Короткие остановки, когда водитель не нажал «Пауза», могут повлиять на оценку. Если Android принудительно завершит сервис, приложение восстановит сохранённый статус при штатном перезапуске сервиса, но это необходимо проверить на конкретном телефоне и с настройками энергосбережения производителя. Проект не был собран Gradle и не проверялся на физическом устройстве в этой среде.

## Обновление 1.7.0 — восстановление GPS и защита фоновой записи

Добавлено:
- GPS-служба переведена на `START_STICKY`: Android может пересоздать её после завершения процесса системой; при восстановлении состояние рейса, тип пробега, ставка и пауза читаются из сохранённых настроек.
- Добавлен `TrackingBootReceiver`: после `BOOT_COMPLETED` и обновления приложения проверяется сохранённый активный рейс и выполняется попытка восстановить foreground GPS service.
- Для автоматического восстановления после перезагрузки Android 10+ требуется разрешение геолокации «Разрешить всё время» (`ACCESS_BACKGROUND_LOCATION`). Если его нет, receiver намеренно не запускает GPS из фона.
- Постоянное уведомление foreground service показывает состояние записи; при отключённом GPS или отсутствии разрешения выводится предупреждающий статус.
- Состояние рейса и паузы записывается синхронно в SharedPreferences перед завершением обработки команды.
- После восстановления службы предыдущая GPS-точка сбрасывается. Поэтому интервал, когда приложение/телефон не записывали координаты, не превращается в оплачиваемый километраж.
- Добавлена последовательная запись GPS-точек и начислений, чтобы конкурентные callbacks не переставляли порядок записей.

Настройка телефона перед поездкой:
1. В разрешениях приложения включите точную геолокацию и, если доступно, «Разрешить всё время».
2. Разрешите уведомления для «Мои Рейсы».
3. В настройках батареи телефона отключите оптимизацию/ограничение фоновой работы для приложения (названия пунктов зависят от производителя).
4. Начинайте рейс из открытого приложения и не нажимайте системную команду «Остановить принудительно».

Ограничения Android:
- Автовосстановление после перезагрузки возможно только если Android разрешает запуск location foreground service из boot receiver и выданы нужные разрешения. Если производитель блокирует автозапуск/фон, потребуется открыть приложение и нажать «Продолжить».
- После команды «Остановить принудительно» (Force stop) Android блокирует автоматические запуски приложения до следующего ручного открытия. Приложение не пытается обходить это системное ограничение.
- Если водитель вручную нажал «Стоп», активный рейс считается завершённым для GPS-восстановления.
- После перезагрузки/аварийного завершения службы непрерывность маршрута на период отсутствия GPS-точек не гарантируется; пробег за этот разрыв не начисляется.
- Требуется проверка на физическом телефоне: поведение энергосбережения зависит от производителя и версии Android. Gradle-сборка и тестирование на устройстве в этой среде не выполнялись.

## Обновление 1.8.0 — резервное копирование и восстановление

Добавлено:
- экспорт одного ZIP-архива через системный выбор места сохранения;
- в архив включаются рейсы, дневные начисления, GPS-точки, остановки, метаданные документов и настройки приложения;
- содержимое вложенных документов копируется в архив, если Android всё ещё предоставляет приложению доступ к исходному URI;
- восстановление из ZIP с предварительным подтверждением, поскольку оно заменяет текущие записи;
- восстановленные вложения копируются в приватную папку приложения и открываются через Android FileProvider;
- восстановление данных выполняется в транзакции Room: при ошибке транзакция базы данных откатывается;
- схема Room не менялась, существующие данные и миграции сохранены.

Как сделать копию: откройте «Настройки» → «Создать копию», выберите папку и сохраните ZIP. Для восстановления выберите «Восстановить», укажите архив и подтвердите замену данных.

Рекомендации:
- сохраняйте ZIP не только на телефоне, но и в облаке/на компьютере;
- перед восстановлением создайте копию текущих данных;
- при переносе на другой телефон восстанавливайте архив после установки приложения;
- если у документа отозван доступ к исходному файлу, его метаданные сохранятся, но сам файл может не попасть в архив. Проверьте, что важные вложения включены в резервную копию.
- восстановление не запускает автоматически GPS-службу из резервного состояния; активный рейс следует открыть и запустить вручную после проверки разрешений.

Ограничения: резервное копирование и восстановление добавлены в исходный код, но не проверены на реальном устройстве. APK не собирался; требуется проверить экспорт/импорт, открытие восстановленных вложений и перенос архива между телефонами.


## Обновление 1.9.0 — автоматическое резервное копирование

Добавлено:
- ежедневное фоновое резервное копирование через Android WorkManager;
- включение/выключение расписания в «Настройки → Автоматическая копия каждый день»;
- архив включает те же данные и вложения, что и ручная резервная копия;
- копии сохраняются в приватной памяти приложения; автоматически оставляются семь последних успешных архивов;
- дата последней успешной копии показывается в настройках;
- повтор при временной ошибке; интернет для локального резервирования не требуется.

Важно: автоматические копии находятся во внутренней памяти приложения и будут удалены при удалении приложения/очистке его данных. Поэтому для защиты при потере или поломке телефона регулярно используйте ручное «Создать копию» и сохраняйте ZIP вне телефона. WorkManager запускает задачу с учётом системных ограничений, поэтому «каждый день» означает примерно раз в 24 часа, а не точное время. Автоматическое сохранение во внешнее облако не выполняется. APK и работу фоновой задачи на физическом устройстве необходимо проверить.


## Версия 2.1.0 — полный финансовый отчёт

- Единый отчёт: доход от пробега, расходы на топливо, прочие расходы и чистый результат.
- Категории расходов: платные дороги, стоянка, ремонт, обслуживание, мойка и прочее.
- Запись расхода с суммой, комментарием и необязательной привязкой к рейсу.
- Периоды: сегодня, неделя, месяц, всё время.
- Показатели: пробег с грузом/без груза, прибыль и расходы на километр.
- Расходы включены в резервное копирование и восстановление; старые архивы без массива `expenses` совместимы.
- Для защиты от двойного начисления в группе рейс/день/тип пробега GPS-записи имеют приоритет над ручными записями. Если в этот день по этому типу есть GPS-данные, ручная запись той же группы в отчёте не суммируется.

Примечание: отчёт считает заправки по дате заправки, а не по дате рейса; это денежный отчёт движения средств, а не бухгалтерское распределение затрат по километрам. Средняя прибыль на километр — ориентир за выбранный период.
